## Fix round 1 — complete analytics infrastructure boundary

Implemented in separate review-fix commit `7eb35b4` on base `c9a2a6f`.

Independent review found that the first classifier inspected only `aws_lambda_function.stats_aggregator`. A plan that left that Lambda and its checked ZIP unchanged but changed `aws_cloudwatch_event_rule.stats_aggregator_daily` from disabled to enabled therefore reported `analytics_change=false` and allowed the automatic push path. This was an Important release-gate defect because the schedule can reopen producer admission without establishing D4's no-writer and durable-backup prerequisites.

Ruling22 defines the maintained boundary. The classifier now requires manual cutover attestation for any non-no-op plan action on:

- the analytics Lambda, schedule, target and invocation permission;
- both producer IAM attachments, its role and access policy;
- the shared data table, producer log group and producer alarm;
- the log-source bucket, versioning, ownership, CloudFront-delivery policy and lifecycle configuration;
- website versioning, whose mutation changes recoverability of the published stats object.

Website-bucket create/delete/replacement is also caught because it changes storage identity. In-place website-bucket updates stay on the ordinary path. CloudFront distribution classification is field-scoped: changed `logging_config` or an actual `true` unknown leaf below `after_unknown.logging_config` requires attestation. Identical logging plus Terraform's empty-schema placeholder `[{}]` does not. This preserves the intended automatic path for the c9 real plan's cache/error update and for unrelated routing, CORS, contact, website-access-log and removed self-logging changes. The classifier is an explicit dependency map rather than a general Terraform dependency engine.

The stronger bootstrap rule is unchanged: only analytics-Lambda create/replacement sets `requires_reader=true`. Manual attestation remains an operator decision and does not prove admission freeze, writer/queue drainage, backup integrity or recovery readiness.
